# KCIB

ระบบจองเครื่องมือ ภาควิชาวิศวกรรมเคมี สจล. หน้าเว็บอยู่ใน `index.html`, `css/` และ `js/`

## กติกาการจอง

- การจองใหม่ใช้รหัสสั้นรูปแบบ `BK-12AB34CD` และตรวจรหัสซ้ำภายใน booking lock ก่อนบันทึก รหัสการจองเดิมยังใช้งานได้
- ต้องกรอกรหัสนักศึกษาก่อนส่งคำขอจองหรือบันทึกโปรไฟล์ ยกเว้นบัญชีที่มีรายชื่อใน StaffConfig (รวมอาจารย์) โดยเซิร์ฟเวอร์ยืนยันบัญชี Google และตรวจรายชื่อล่าสุดก่อนยกเว้น ไม่ขึ้นกับบทบาทที่กำลังเลือกอยู่
- ทุกหมวดจองล่วงหน้าอย่างน้อย 3 วันทำการ โดยไม่นับวันปัจจุบัน เสาร์–อาทิตย์ และวันหยุดจากชีต Holidays ตามเวลาไทย
- เวลาใช้งาน 09:00–16:00 น. ช่วงเวลาปกติเลือกได้ 1, 2 หรือ 3 ชั่วโมง
- เตาเผา เตาอบ HPLC GC เครื่องแก้ว และอุปกรณ์วิทยาศาสตร์ระบุวัน/เวลาเริ่มและสิ้นสุดเองได้
- อาจารย์ที่ปรึกษา → หัวหน้าภาคอนุมัติ จบขั้นตอนการอนุมัติ เจ้าหน้าที่ดูรายการและสถานะได้โดยไม่ต้องกดรับทราบ
- ผู้มีหลายบทบาทสลับได้เฉพาะบทบาทใน StaffConfig การอนุมัติตรวจบัญชี Google และสิทธิ์ซ้ำที่เซิร์ฟเวอร์
- รายการสถานะเดิม “รออนุมัติขั้นที่ 3” แสดงเป็น “อนุมัติแล้ว” โดยไม่แก้ประวัติในชีต และไม่นับเป็นรายการรอดำเนินการ

## ตรวจสอบ

หน้า `#calendar` แสดงตารางจองแบบสัปดาห์ เดือน และรายการ พร้อมกรองหมวด ห้อง/Team Project 2 และอุปกรณ์ ปุ่มดูตารางจองบนการ์ดเปิดปฏิทินของอุปกรณ์นั้นได้โดยตรง

API `getCalendar` รับ `from` และ `to` เป็นวันที่ โดยไม่รวมวัน `to` และจำกัดช่วงไม่เกิน 42 วัน ส่งกลับเฉพาะรหัสอุปกรณ์ วันเวลา จำนวน และสถานะ ไม่ส่งชื่อ อีเมล หรือข้อมูลโปรไฟล์ของผู้จอง ช่วงเวลาว่างในปฏิทินตรวจซ้ำในแบบฟอร์มและตอนบันทึกการจอง

API `getAvailability` รับ `itemId`, `from` และ `to` แบบไม่รวมวัน `to` เช่นเดียวกัน รองรับช่วงไม่เกิน 181 วันสำหรับการจองหลายวัน และส่งเฉพาะข้อมูลเวลาที่ถูกจองของอุปกรณ์นั้น ตะกร้าใช้ cache 10 วินาทีร่วมกันเมื่อเปลี่ยนจำนวนหรือชั่วโมงภายในช่วงวันเดิม

ข้อมูลเริ่มต้นสำหรับแสดงรายการมี cache ฝั่ง Apps Script 60 วินาทีและในแท็บเบราว์เซอร์ 5 นาที เปิดหน้าใหม่ภายในอายุ cache ใช้ข้อมูลเดิมโดยไม่เรียกเซิร์ฟเวอร์ซ้ำ ปุ่มรีเฟรชข้าม cache นี้ การจองและการอนุมัติอ่านข้อมูลและสิทธิ์จากชีตล่าสุดเสมอ

รายการจองสำหรับแสดงผลมี cache 10 วินาที และเปลี่ยน cache key หลังเขียนข้อมูลทุกครั้ง ปฏิทินเก็บข้อมูลช่วงวันเดิมในเบราว์เซอร์ 10 วินาที จึงเปลี่ยนตัวกรองได้โดยไม่โหลดซ้ำ ปุ่มรีเฟรชและปุ่มลองใหม่ข้าม cache การจอง ยกเลิก อนุมัติ และปฏิเสธสำเร็จจะล้าง cache ที่เกี่ยวข้องในหน้าเว็บด้วย

แจ้งเตือนใช้ POST `getNotifications` พร้อม Google ID token และบทบาทที่เลือก เซิร์ฟเวอร์ยืนยันบัญชีและสิทธิ์ก่อนส่งจำนวน รายการไม่เกิน 10 รายการ และสถานะสำหรับทำเครื่องหมายว่าอ่านแล้ว หน้าเว็บเก็บสรุปนี้ 30 วินาที จึงไม่ต้องโหลดประวัติจองทั้งหมดเพื่อแสดงกระดิ่ง ส่วนประวัติเต็มโหลดเมื่อเปิดหน้าการจองหรือแดชบอร์ด

Google Sans โหลดผ่าน Google Fonts embed ใน `index.html` และคง Sarabun เป็นฟอนต์สำรองภาษาไทย

การอนุมัติ/ปฏิเสธส่งแถวที่อัปเดตกลับมาให้หน้าเว็บใช้ต่อโดยไม่โหลดตารางซ้ำ คำสั่งทั้งหมดส่งเป็นชุดละไม่เกิน 200 รายการ และรายงานรายการที่สำเร็จหรือไม่สำเร็จแยกกัน

```sh
node --test tests/*.test.cjs
```

## Apps Script

ใช้ `code.gs` เป็น backend หลัก และ `js/booking-rules.js` เป็นกติกาที่ใช้ร่วมกับหน้าเว็บ ต้อง deploy ทั้งสองไฟล์พร้อมกัน ผ่าน `.clasp.json` เดิม

`.claspignore` จำกัดไฟล์ที่ส่งไว้เป็น `code.gs`, `js/booking-rules.js` และ `appsscript.json` เท่านั้น

บัญชีผู้ deploy ต้องเปิด Google Apps Script API ที่ https://script.google.com/home/usersettings ก่อนอัปโหลด

```sh
clasp status
clasp push
clasp deploy --deploymentId <deployment-id-เดิม> --description "Booking rules and staff viewing"
```

คอลัมน์รับทราบเดิม `StaffAcknowledgedAt` และ `StaffAcknowledgedBy` เก็บไว้เป็นประวัติ ระบบไม่เขียนข้อมูลรับทราบเพิ่ม ชื่อบทบาทและรายชื่อสมาชิกอยู่ใน StaffConfig

หน้าเว็บ deploy ผ่าน GitHub Pages เมื่อ push เข้า `main` ธีมและบทบาทที่เลือกล่าสุดบันทึกเฉพาะในเบราว์เซอร์
